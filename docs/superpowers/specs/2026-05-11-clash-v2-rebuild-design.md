## Problem Statement

当前 PULSE 已上线的"复刻皇室战争 + 健身联动"版本（Day 15-20，15 个 commit 累积到 main）在用户首次完整试玩后暴露五个严重问题：

1. **新旧两套游戏并存** — 旧 Arena 路由还在 sidebar 显示（"对战 (经典)"），旧 Loot 抽卡、旧 CardLibrary、旧 DeckBuilder 都还活着，旧 Dashboard 引用的还是旧版"健身系列"卡组（IconBarbell 等），跟新 Clash 卡组（骑士/弓箭手）完全脱节。评审同时看到两套游戏 = 产品判断不清晰。
2. **新 Clash 内部也有重复设计** — `ClashCards`（卡库）和 `ClashDeck`（卡组配置）是两个独立页面，没必要拆。
3. **P0 阻塞 bug：单位无法过桥** — 用户实测部署单位后过不了 river，永远到不了对面塔。前一轮我自己 browse 测试时只验"部署成功"没验"推塔成功"，验证不充分。
4. **视觉观感差，离皇室战争太远** — 当前 `Battlefield.tsx` 是 DOM div + emoji 角色（🛡️🏹💀），CSS transform 移动，零帧动画，零特效。emoji 本身就是 OS 渲染，跨平台还不一致。用户原话："角色看起来没有质感，完全没有达到复刻皇室战争的水平"。
5. **Onboarding 重点错位** — 当前 4 步：欢迎 → 选运动 → 模拟打卡 → 旧 Loot 抽卡。完全没有 Clash 教学局，没有皇室战争式的"首抽包翻牌仪式感"，新用户进来不知道这是要打牌。

用户的明确诉求：删旧版、修 bug、视觉质感大幅跃迁、onboarding 重做、整体设计感全面提升。

## What Makes This Cool

"运动打卡 → 金币入账 → 抽卡爽感 → 上桌对战"这条 Clash Royale 经典闭环被 5 亿玩家验证过是有成瘾循环的。PULSE 把"金币"挂到健身打卡上的同时——把跑步 30 分钟变成"开传说宝箱"前奏——情绪等价于"健身房撸完铁去拆快递"。

视觉做到 7/10 接近原版皇室战争质感后，"我刚跑完步换来一张闪光稀有卡"的爽感才真正落地。当前 emoji 状态下这条情绪链是断的。

## Constraints

- **测评作业，非上线产品**。评判维度 = 产品思考完整度 + 评审在线亲自体验。要踩到这两条上。
- **不能使用 Supercell 的 IP 资产**（皇室战争原版立绘、动画帧、音效、贴图）。必须 AI 生成或公开授权素材。"复刻"是风格/玩法层，不是像素级抄。
- **DESIGN.md 已锁定暗黑霓虹基调**（accent #b6ff3c、Satoshi/Instrument Sans/JetBrains Mono、4px 卡片圆角、glow halo）。Pixi 渲染层必须继承同一套色板，不能搞两套美学。
- **栈约束**：Vite 5 + React 18 + TypeScript strict + Tailwind v3 + Supabase + Bun。新增依赖只能加 `pixi.js@^8` + 可选 `@pixi/react`。bundle 不能超过 1.5MB gzipped（当前 ~500KB）。
- **后端不动**。`cr_*` schema 已稳定（migrations 24-27 已 push），8 个 RPC 不重写。所有改动集中在前端渲染层 + Onboarding 流程 + 旧版下架。
- **scope 偏好：大胆 > 保守**，宁愿跨多天完整交付也不接受"砍功能保工期"（来自用户 memory）。
- **响应语言**：所有交付 UI/文档继续中文（用户 memory + CLAUDE.md §0）。

## Premises

需要用户明确认可，决定后续 plan 是否成立：

1. **100% 还原皇室战争不可行也不应该追**。原因：IP 版权（不能抄角色立绘）+ 美术资源（原版每卡 ~60 帧 sprite 是 Supercell 数十人多年工作）+ 评判维度不匹配（评的是产品思考不是图形质量）。**目标改为视觉质感从 1/10 跃迁到 7/10，让评审一眼觉得"这是个真游戏不是 demo"**。
2. **DOM + emoji 是当前架构的视觉天花板**。即使把 emoji 换 SVG icon 也到不了"卡通角色立绘 + 帧动画 + 粒子"的质感。要质变必须换渲染层。
3. **Pixi.js v8 是 2D Web 游戏渲染的行业标准**（MIT，PIXI 团队维护，2024 年 v8 正式版，60fps 稳定）。引入它本身就是一段值得在评审材料里讲的产品/技术决策——"为什么选 Pixi 而不是 Three.js / Canvas 裸写 / Phaser"。
4. **过桥 bug 必须独立修，不能寄希望于引擎重写顺便消失**。pathfinding 是引擎逻辑层，跟渲染无关。换 Pixi 渲染层后这个 bug 还在。需要单元测试覆盖（left/center/right 三条 lane）。
5. **旧版必须彻底物理删除而不是降级到"经典"标签**。理由：(a) 同时维护两套游戏没意义；(b) 评审看到两套游戏会觉得产品判断不清晰；(c) 删旧版释放 sidebar 空间和 Dashboard 空间给新 Clash 闭环。
6. **Onboarding 的核心情绪是"我刚开始就拿到了好东西"**。当前 4 步是功能性 onboarding（先选偏好再去玩）。皇室战争式是叙事性 onboarding（先有故事 → 给你大礼包 → 进入教学局）。要重做。

## Approaches Considered

### Approach A: Pixi.js 引擎跃迁 + AI Sprite 包（已选定）

- **战场渲染层**：`pixi.js@^8` 替换 `src/clash/components/Battlefield.tsx` 的 DOM transform 渲染。Pixi Application 挂在 `<canvas ref>`，60fps RAF，read MatchState from useClashEngine hook each frame.
- **角色 sprite**：用 **OpenAI gpt-image-2 API** 生成 12 个角色 × 4 状态 (idle/walk/attack/death) = 48 张高质量静态 PNG。
  - **Pilot batch first**（Codex T7 fix #6）：Day 23 先出 4 张 pilot（knight + archer + valkyrie + dragon），集成进 PixiBattlefield 实际渲染评估，**人工通过后**才扩到 12 角色全集。pilot 不达标的话 prompt 调完重生成，避免 48 张全做完才发现风格漂移。
  - **QA gate**（Codex fix #4）：每张生成后 3 条检查 — (a) 透明背景没有 artifact，(b) 1.5px 黑色 outline + neon lime weapon glow 落地，(c) 角色 silhouette 在 64×64 缩略下仍可辨识。不通过的 prompt 调整后重生成。
  - **风格 prompt 锚定**：先出 1 张 knight 参考立绘（1024×1024）人工把关，后续用 reference image 模式锚定。
  - **资源优化**（Codex T3 fix #2）：48 张 PNG (512×512 transparent) 实际 ≈ 5-15MB，必须做：(a) WebP 转换（payload ~30-50% 降幅），(b) 同 card 4 状态合并 spritesheet atlas（HTTP 请求数 48→12），(c) 实际 payload 预算改为 ≤ 3MB lazy-loaded（**非 gzipped 体积，是真实网络传输**）。
- **角色动作**：**不靠帧动画，靠前端 tween 驱动**。idle 上下 2px 呼吸 bob；walk 左右 swing 5°；attack forward thrust 10px + 闪光；death rotate 90° + fade。Pixi 自带 `Ticker` + 手写 lerp，比帧切换更丝滑，sprite 总数 = 48 张静态图。
- **Sprite lifecycle reconciliation**（Codex T6 fix #9）：PixiBattlefield 维护 `Map<entity_id, PIXI.Sprite>`。每帧根据 useClashEngine state diff：state 里有新 entity_id = create sprite；entity 消失 = destroy sprite + 释放 texture；entity 存在 = update transform。这避免 dead unit、duplicated projectile、texture leak。
- **特效**：粒子（攻击命中 30 颗 neon green 粒子）、弹道（弓箭/火球抛物线，Pixi Graphics 绘制）、塔倒塌（sprite fade + shockwave ring + 200ms 屏幕震动 via CSS）、入场烟雾（部署位置 0.3s puff）。
- **逻辑层修复**：`src/clash/engine/pathfinding.ts` 的 `nextWaypoint` 修过桥 bug，加单元测试覆盖三条 lane × 双向。
- **旧版清理**：删除 6 个旧 page 文件 + 旧 component 目录 + 旧 i18n keys + Sidebar 从 12 项简化到 5 项。
- **卡牌系统合并**：`ClashCards` + `ClashDeck` → `ClashCollection` 单页内 tab 切换。
- **Onboarding v2**：4 步重做（叙事 → 第一次打卡 → 首抽包翻牌动画 → 教学局必胜）。
- **人力估算（user-side）**：~3-4 天 / **CC 估算**：~6-8 小时纯写代码。
- **完整度**：9/10。

### Approach B: DOM 视觉深度提升 + 决策文档（落选）

- 留 DOM 不换引擎，emoji → AI 生成静态 PNG cartoon sprite（无帧动画）
- CSS keyframes 模拟攻击挥砍 + Framer Motion 入场
- 写"为什么不上 Pixi"决策文档塞评审材料
- 视觉从 1/10 → 5/10，到不了卡通角色立绘的丝滑
- **落选理由**：用户明确说"观感很差"，B 是中等改善不是质变。用户 memory 偏好大胆 > 保守。

### Approach C: PM 思考极致版（落选）

- 不动视觉，只删旧版 + 修 bug + 重做 onboarding + 写厚一倍的产品思考文档
- 0.5 天交付，最低风险
- **落选理由**：不解决用户已明确抱怨的"观感"核心问题。

## Recommended Approach

**Approach A — Pixi.js 引擎跃迁**。

理由链：
1. 用户 memory 锁定"大胆 > 保守"+"宁愿跨多天交付完整版"
2. DOM 视觉天花板已被实证不够（用户原话"观感很差"）
3. Pixi v8 引擎选型本身就是高质量产品/技术决策，写进评审材料 = 加分项
4. AI sprite 在 2026 年质量已稳定（OpenAI gpt-image-2 出卡通角色一致性 + transparent PNG + 风格锚定已成熟）
5. 过桥 bug + 旧版清理 + onboarding 重做这三块是无论选 ABC 都必做的，A 把它们顺带做掉

## Open Questions

留给 plan-eng-review 阶段决策：

1. **AI sprite 生成 API 已锁定 OpenAI gpt-image-2**（用户指定）。剩下要决策的子项：(a) 一次 prompt 出整张 spritesheet（12 帧 grid，省 API call 但切片更难）还是单帧逐张生成（风格更稳但 API 调用 ×12）？(b) 角色风格锚定怎么做——先生成 1 张参考立绘 → 后续 prompt 引用"same style as reference image"，还是每次重写完整风格描述？倾向 (a) 单帧逐张 + (b) 参考立绘锚定，因为单帧 PNG 后期切分用脚本可控，参考图锚定能让 12 个角色保持一致的笔触/色板/线粗细。
2. **动作驱动用什么 tween 库**？GSAP（行业标准 + Pixi 集成成熟 + 商用付费但 free tier 够用）vs Pixi 自带 `Ticker` + 手写 lerp（零依赖但样板代码多）vs Framer Motion（声明式但更适合 DOM 不是 Pixi）。倾向 Pixi `Ticker` + 手写 lerp，因为动作只有 4 种 state，每个就 5-10 行 lerp 不值得引第三方。
3. **Pixi v8 + React 18 集成模式**——`@pixi/react` 声明式 `<Stage>/<Sprite>` 还是手写 `<canvas ref>` + 直接 PIXI.Application API？倾向后者，因为渲染是 imperative 不适合声明式，且 `@pixi/react` 历史上跟 Pixi 主版本同步有延迟。
4. **教学局难度设计**——脚本化"喂招"必胜 vs 简单 easy difficulty。倾向脚本化，因为新手第一局必须赢（皇室战争原版就是这么做的）。
5. **音效**——皇室战争原版音效是 Supercell IP 不能用。要不要花时间找 CC0 音效或 AI 生成？倾向 v2 再加，v1 静音。
6. **bundle 体积**——Pixi v8 minified ~300KB + gzipped ~120KB，加 sprite 资源 PNG 总 ~500KB-1MB（lazy load on /clash/match only）。需要 chunk split 让 dashboard 不加载 Pixi。

### Day 22 — Pixi.js 接入 + 战场基础场景 + lazy split

1. `bun add pixi.js@^8`（不加 @pixi/react，手写 canvas）
2. 新建 `src/clash/render/PixiBattlefield.tsx` 替换 `Battlefield.tsx`，对外 API 不变（接 useClashEngine state + deploy 回调）
3. **React.lazy + Suspense（Codex T4/D4）**：`ClashMatch.tsx` 用 `const PixiBattlefield = React.lazy(() => import('@/clash/render/PixiBattlefield'))` + Suspense fallback "战场加载中…"。Dashboard / Workout / ClashHome / Collection 永不加载 Pixi chunk。Vite 自动 chunk split。
4. **坐标映射 spec（Codex T6 fix #10）**：
   - logical board = 18 cols × 32 rows
   - canvas px size = `min(viewport.width × 0.9, 720)` × `min(viewport.height × 0.85, 1280)`，**保持 18:32 aspect ratio**
   - logical→pixel: `px_x = (col / 18) × canvas.width`，`px_y = (row / 32) × canvas.height`
   - 移动端 (< 768px): canvas 占满宽度，高度按 aspect 计算
   - desktop: canvas 居中，左右留 sidebar 空间
   - PointerEvent 坐标 → board 坐标：reverse 上面映射
5. 实现：暗黑霓虹背景（`#0a0e1a`）+ 18×32 grid 微辉光（rgba(182,255,60,0.04) 1px 线）+ river 蓝色半透明 (`rgba(60,140,255,0.25)` y=15-17 横带) + 2 座桥（暖棕 `#8b5a2b` rect, x=3 和 x=14）+ 6 塔（彩色 rect 占位 + 塔身 hp bar）。**全部颜色读 CSS variable**，不 hardcode 漂移。
6. **RAF loop driven by useClashEngine state ref（D5）**：useClashEngine 暴露 `stateRef.current`，Pixi `Application.ticker.add()` 每帧读 ref。
7. **Sprite reconciliation Map 骨架（D9 fix）**：维护 `entityMap = new Map<id, PIXI.Sprite>()`。每帧 diff `state.units` 和 `state.towers`：新 id → create sprite + add to stage；消失 id → `sprite.destroy({ texture: false })` 并 entityMap.delete；存在 id → 更新 sprite.x/y/scale/rotation。

#### 步骤 4 — 一次性生成脚本 `scripts/gen-sprites.ts`

```ts
// 伪代码骨架
import { writeFileSync } from 'fs'
const REF_IMG = 'public/sprites/_ref/knight-anchor.png'
const PROMPT_TPL = `Game sprite of a {desc} in {state} pose,
dark fantasy cartoon style, isometric 3/4 view,
1.5px black outline, neon lime (#b6ff3c) accent on weapon/magic,
dark navy color palette, transparent PNG background,
single frame centered, 256x256 character on 512x512 canvas.
Style reference: match the provided knight anchor image.`

for (const card of CARDS_12) {
  for (const state of ['idle', 'walk', 'attack', 'death']) {
    // 3 次指数退避重试 (1s, 4s, 16s) 处理 rate limit
    const png = await callGptImage2WithRetry({
      prompt: PROMPT_TPL.replace('{desc}', card.desc).replace('{state}', state),
      reference_image: REF_IMG,
      size: '512x512',
      response_format: 'b64_json',
    })
    writeFileSync(`public/sprites/raw/${card.id}-${state}.png`, png)
  }
}
```

错误处理：API rate limit → 指数退避 3 次；3 次后失败 → 记 `retry-queue.json` 留人工重跑；不阻塞其他角色。

### Sprite 规格

- **Outline**：1.5px solid black，无 anti-alias 模糊
- **Camera**：isometric 3/4 view（不是正面、不是俯视）
- **Character size**：256×256 pixel art 在 512×512 transparent canvas 中央
- **In-arena display size**：18×32 board × 36×30px logical → sprite 大小 ~24×40 px @ 720×1280 canvas
- **Color palette**：dark navy base + neon lime (#b6ff3c) weapon/magic accent + rarity 4 色边框
- **Silhouette test**：64×64 缩略下，4 个原型（人形 / 远程 / 女性 / 怪物）必须能从 silhouette 区分
- **Transparency**：alpha 8-bit，无白底 fringe

### Animation 规格

- **idle bob**：sin(t × 2π / 1500ms) × 2px vertical bobbing，breathing rhythm
- **walk swing**：lerp rotation -3° → +3°，500ms cycle，伴随脚下灰尘 puff
- **attack thrust**：sprite.x += 10px forward + tint flash (#ffffff alpha 0.5 → 0) 100ms 内
- **death**：rotation lerp 0° → 90° + alpha 1 → 0 over 500ms，落地 puff

### 特效规格

- **Particles**：30 颗 neon green 圆点 (radius 2-4px) 从 hit position 随机方向飞，0.5s fade
- **Projectile**：抛物线 4-line Graphics 0.4s 飞行 + 命中 ring expand 100ms
- **Tower destroy**：sprite fade 0.8s + 300px ring + CSS screen shake 200ms (transform: translate ±4px)
- **Hit flash**：tint white 100ms then back
- **Z-order**：towers > flying units > ground units > particles > river > grid bg

### Readability 重叠时

- 单位重叠时，z-order 按 y 排序（前低后高）
- HP bar 永远 visible 在 sprite 顶部，不被遮挡
- 攻击连接线（弹道）alpha 0.7 半透明，不挡视野

## Failure Modes

来自 D9 决策。5 个生产场景 + 用户看到什么 + mitigation。

### 1. 低端机 Pixi <60fps

- **场景**：旧 Android / 老 Macbook Air，Pixi 测得 <45fps
- **用户看到**：unit movement 卡顿，攻击粒子掉帧
- **Mitigation**：Pixi `Ticker.FPS` 监控，连续 60 帧 < 45fps 触发降级（关粒子 + 30fps cap + 静态 sprite）。Dev mode 显示提示，正常用户透明降级。
- **测试**：Chrome DevTools throttling "4x slowdown" CPU 验证

### 2. Sprite 加载失败

- **场景**：用户网络中断 / Vercel CDN 故障，PIXI.Assets.load() 失败
- **用户看到**：进 /clash/match 后 "战场加载失败 · 重试 / 返回" 错误屏
- **Mitigation**：`useClashAssets` hook try-catch，失败时 setError + 显示 fallback UI。Retry 按钮重新触发加载。
- **测试**：Chrome DevTools Network "offline" 进 /clash/match

### 3. gpt-image-2 API 失败（Day 23）

- **场景**：rate limit / API key 失效 / 模型过载
- **用户看到**：仅影响开发者，不影响 production 用户
- **Mitigation**：`scripts/gen-sprites.ts` 3 次指数退避；3 次后失败的角色记 `retry-queue.json`，人工 day 23 末尾手动重跑；如果整批失败，临时用 emoji + outline 占位 sprite 顶上（不阻塞 Day 24 节奏）。
- **测试**：模拟 API timeout 验证重试 + queue 写入

### 4. Tutorial 用户不动手

- **场景**：用户进 Step 4 教学局后 60 秒内不部署任何 unit
- **用户看到**：屏幕中央淡入 hint "拖动手牌部署到桥边" pulse 提示，30 秒后再淡入第二条 "卡牌在屏幕底部 · 长按拖到桥位"，60 秒后第三条 "跳过教学? [跳过]" 出现跳过按钮
- **Mitigation**：tutorial.ts 用 inactivity timer，多级提示降级 + 跳过出口（跳过后 localStorage 标记 `tutorial_skipped = true`，不影响 onboarding_completed_v2）
- **测试**：e2e 等待 60s 不操作 → 验证 3 级提示出现 + 跳过按钮可点

### 5. 离线进 /clash

- **场景**：评审离线后回来 / 网络抖动
- **用户看到**：useClashState 失败 → ClashHome 显示 "数据未就绪 · 请检查网络 [重试]"，已加载的 sprite 仍然可见但不能 deploy
- **Mitigation**：React Query 自带 retry + 网络监听，回连后自动 refetch；Pixi 渲染层不依赖网络
- **测试**：DevTools Network offline 模式 + 验证错误屏 + 回连后自动恢复
